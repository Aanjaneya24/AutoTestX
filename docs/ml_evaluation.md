# ML evaluation

Generated by `python -m autotestx evaluate-ml --out reports/ml_evaluation.json` (seed 42). Numbers below are copied from
that file; rerun to reproduce. The numbers are only meaningful with the caveats at the end.

## Data

- `data/labeled_log_snippets.csv`, produced by `scripts/make_dataset.py` (seed 1234).
- 151 samples, **all synthetic** (`source_type=synthetic`): hand-written message templates modelled on typical
  simulator/tool wording, each filled with random numbers, files and signal names. No real or proprietary logs.
- Labels: compile_error 29, assertion_failure 32, timeout 32, runtime_error 29, unknown 29. 40 template "families"
  (8 per class); the one-line families (e.g. "Segmentation fault") yield a single sample, hence the unequal counts.

## Method

- Model: normalise (lowercase, mask numbers/hex/source file names) -> TF-IDF (1-2 grams, sublinear) -> LogisticRegression (C=10).
- Split: `StratifiedGroupKFold(4, shuffle, seed 42)` grouped by `family_id`. All variants of a template stay on one side, so a
  test message is never a number-swapped copy of a training message. Metrics are on pooled out-of-fold predictions (151 samples).
  This is deliberately strict: every test message uses wording the model never saw in training.
- Baseline: keyword rules in `log_analysis.rule_classify`, no training.
- Single-sample inference: about 0.15 ms (mean of 50 `predict_proba` calls, this machine).

## Reading the result

- **The rules beat the model on this data.** That is reported as measured; the model is not claimed to improve anything.
- Rules have perfect precision on three classes but miss any paraphrase they have no keyword for (these fall to `unknown`,
  which is why `unknown` recall is 1.00 and precision low).
- The model learns word cues from only ~110 training samples per fold; held-out families with new wording confuse it.
  Examples from the seed-42 run: "elaboration aborted: design unit ... could not be resolved" (true `compile_error`) is
  predicted `runtime_error` by the model and `unknown` by the rules; "UVM_ERROR ... did not match reference model"
  (true `assertion_failure`) is predicted `timeout` by the model and `unknown` by the rules.
- Where each is better: rules for highly structured, known tool messages; ML only has a chance to help with varied phrasing,
  which needs far more (and real) data than exists here.

## Caveats (important)

- Synthetic, template-generated data: even grouped splitting cannot make it representative of real logs.
- The rule baseline was written by the same author who wrote the templates, so it is likely optimistic.
- **Effective sample size is small.** The 151 rows come from 40 template families; after masking numbers and file names only
  92 distinct texts remain (audit, 2026-10-09). Per-class "support" counts therefore overstate how much independent evidence there is.
- **The ML score depends on the split seed.** Audit re-runs of the same protocol with other seeds: ML macro-F1 0.569 (seed 0),
  0.440 (1), 0.581 (7), 0.600 (42), 0.509 (99). The rule baseline is 0.752 for every seed because it is not trained. The rules
  beat the model on all five seeds, but treat any single ML figure as roughly 0.44-0.60.
- The model classifies text, not hardware faults. Inside `run`, predictions appear in a separate column and never change PASS/FAIL.
